# Split `run_dnn.py` into `train.py` and `evaluate.py`

## Context

`pytorch/run_dnn.py`'s `run(params)` (`run_dnn.py:38-449`) is one monolithic function that does environment/logging setup, data loading/preprocessing, network creation, training (`<train>`, `run_dnn.py:213-272`), prediction (`<predict>`, `run_dnn.py:274-327`), evaluation (`<evaluate>`, `run_dnn.py:329-359`), and output/plotting (`<output>`, `run_dnn.py:361-449`), all gated by an `argparse --mode` flag parsed into a `dlk.mode.Mode` flag combination. The user wants two independent scripts: `train.py` (runs training only, stops after, including the existing `train_profile` path) and `evaluate.py` (loads a checkpoint written by `train.py` and runs prediction+evaluation), both driven by the same YAML config file (e.g. `pytorch/configs/params_dnn.yaml`).

`run_dnn.py` stays completely untouched (the user will remove it later themselves). A new `pytorch/run.py` is added that chains `train.py` then `evaluate.py` to reproduce `run_dnn.py`'s current default `train_eval` behavior for anyone who still wants one combined invocation.

Three gaps in the current code directly affect this split, all settled with the user:

- **Checkpoint format mismatch (bug)**: `dlk.opt.train.train_epochs` checkpoints via `dlk.opt.utils.checkpoint_save`, which writes `{"epoch", "model_state_dict", "optimizer_state_dict"}` (`dlk/opt/utils.py:96-123` in `deep-learning-toolkit`). But `run_dnn.py:206`'s weight-loading does `net.load_state_dict(torch.load(net_path, map_location=device))` directly on that dict, which would raise a state-dict-key mismatch today. `evaluate.py` must use `dlk.opt.utils.checkpoint_load` (`dlk/opt/utils.py:126-160`) instead, which correctly unwraps `model_state_dict` and strips any `module.` DDP prefix.
- **No checkpoint auto-discovery for the main network**: unlike the `autoencoder_load_dir` dev block (`run_dnn.py:146-182`), which already globs `checkpoints/*` for the latest timestamp folder and the latest `.pt` file by mtime, the main network's `runconfig.load_dir` (`run_dnn.py:204-206`) must be an exact `.pt` file path today; this misleading name (it needs a file, not a directory) is exactly why the new scripts rename it to `runconfig.load_checkpoint` (see Settled design decisions below). `evaluate.py` adopts the same glob+mtime discovery pattern, but only as a fallback: it loads `runconfig.load_checkpoint` directly (no discovery) when set, and auto-discovers the latest checkpoint under `runconfig.save_dir` when it is not set, so it can find the checkpoint `train.py` just wrote without the user having to hand-edit a file path between runs.
- **Unused work in eval-only mode**: when `mode` has no `Mode.TRAIN` component, `run_dnn.py:184-194` still builds a primary `dataloader` (keyed off `mode_to_data_key="test"`) that is never read again — the actual evaluation loop builds its own `eval_dataloader` dict per split (`run_dnn.py:281-293`). `evaluate.py` drops this dead computation entirely.

### Settled design decisions

- `run_dnn.py` is not edited or deleted in this change.
- New `pytorch/common.py` holds setup/data logic shared by `train.py` and `evaluate.py`: environment+logging setup, random seed, data loading+preprocessing (including the FFT and autoencoder-encoder `features_transform_fn`/`train_input_transform_fn` setup), and a `find_latest_checkpoint` helper.
- `evaluate.py` loads checkpoints via `dlk.opt.utils.checkpoint_load`, fixing the state-dict mismatch bug.
- The runconfig key is renamed from `load_dir` to `load_checkpoint` for `train.py`/`evaluate.py`/`run.py`, since it always holds a path to one `.pt` checkpoint file, never a directory; `run_dnn.py` is modified to also use `runconfig.load_checkpoint` (see Section 5, Config file changes).
- `evaluate.py` uses `runconfig.load_checkpoint` directly as the checkpoint file to load when it is set; when it is not set, `evaluate.py` auto-discovers the latest `checkpoints/*/net_e*.pt` file under `runconfig.save_dir` instead (so the same config file works for both scripts with zero edits when the user is not resuming from a specific checkpoint).
- `train.py` keeps `runconfig.load_checkpoint` as an optional, exact `.pt` checkpoint file path for resuming/fine-tuning (loaded via `checkpoint_load` too, for consistency), unchanged in spirit from today's (buggy) resume path.
- New `pytorch/run.py` chains `train.run_train(params)` then `evaluate.run_evaluate(params)`, reusing the full mode-choice set (`train`, `predict`, `eval`, `train_eval`, `train_predict`, `train_profile`) to match `run_dnn.py`'s current default behavior.
- After `run.py` runs `train.run_train(...)`, it resets `params["runconfig"]["load_checkpoint"] = None` before calling `evaluate.run_evaluate(...)`, so evaluation always auto-discovers the checkpoint `train.py` just wrote instead of reloading whatever checkpoint training resumed from (relevant only when `runconfig.load_checkpoint` was set to resume training).
- `run_train`/`run_evaluate` accept optional `logger`/`device` parameters so `run.py` can build them once (self-name `"run"`) and pass them to both, producing a single `run_{debug,info,error}.log` set instead of separate `train_*`/`evaluate_*` files; standalone `train.py`/`evaluate.py` invocations still get their own separate log files.
- All new file-path handling in `common.py`/`train.py`/`evaluate.py`/`run.py`, including the moved `autoencoder_load_dir` glob+mtime block and the new `find_latest_checkpoint` helper, uses `pathlib.Path` (`Path.glob`, `Path.stat().st_mtime`), not `os.path`/`glob.glob`.
- The active DNN config files each get a new `runconfig.load_checkpoint:` line added and the existing `runconfig.load_dir:` line is removed (see Section 5, Config file changes); the shared `dlk.mgmt.parameters.add_args_to_parser`'s `-l`/`--load_dir` CLI flag (in `deep-learning-toolkit`, out of scope to edit) still only populates `args.load_dir`, this is ignored and will be addressed in the toolkit separately.
- `train_m*.sh` scripts are left untouched (they keep calling `run_dnn.py`, which keeps working).
- `CLAUDE.md` and the repo-root `WARP.md` get brief additions documenting the new `train.py`/`evaluate.py`/`run.py` entry points, alongside (not replacing) the existing `run_dnn.py` documentation.
- No new pytest suite (none exists for this code path today, consistent with the prior `data`/`data_train`/`data_evaluate` split plan); verification is a real smoke run comparing key logged values.

### Core principle

Every piece of setup that both scripts need byte-for-byte (environment, data) moves into `common.py` behind small functions with no `mode`-branching inside them. `train.py` and `evaluate.py` each only contain the logic that is genuinely different between the two (the training loop vs. the predict+evaluate loop). Neither `train.py` nor `evaluate.py` calls the other; `run.py` is the only place that composes both, and it does so by calling their public `run_train(params, ...)`/`run_evaluate(params, ...)` functions directly on an already-loaded `params` dict, never their `main()`. The same one-process-one-setup rule applies to logging: `common.initialize_run` runs exactly once per process, standalone or combined. All new file-path handling uses `pathlib.Path`, not `os.path`.

## Terminology

- **`run_train(params, logger=None, device=None)` / `run_evaluate(params, logger=None, device=None)`**: the public, CLI-independent entry points in `train.py`/`evaluate.py` that take an already-loaded, already-overridden `params` dict and do the actual work. Each accepts an optional pre-built `(logger, device)` pair (see "single log-file set" below); when omitted, it builds its own via `common.initialize_run`. Each script's own `main()` is a thin wrapper that parses CLI args, loads/overrides/saves `params`, then calls its `run_*` function with no `logger`/`device`. `run.py` builds `logger`/`device` once itself and passes them into both `run_*` functions, so params are parsed/saved and logging is set up exactly once for a combined invocation.
- **checkpoint auto-discovery**: given a directory, list `checkpoints/*/net_e*.pt` with `pathlib.Path.glob`, pick the most recently created timestamp subfolder, then the most recently modified `.pt` file inside it by comparing `Path.stat().st_mtime` (mirrors the existing `autoencoder_load_dir` dev block's glob+mtime pattern at `run_dnn.py:154-160`, but with `pathlib` instead of that block's `glob.glob`/`os.path.getmtime`).
- **`common.py`**: new shared module. Not a class or config object, just plain functions that take `params`/`self_dir`/`logger`/`device` and return plain values, so `train.py` and `evaluate.py` stay easy to read top-to-bottom.
- **single log-file set**: `dlk.mgmt.log.logging_set_up` calls `logging.basicConfig(...)` (a no-op on a second call in the same process) and then unconditionally adds new `FileHandler`s to the root logger every time it runs; calling it twice in one process (once for training, once for evaluation) would silently keep the first call's debug log file while duplicating every info/error/console log line across two sets of handlers. `run.py` avoids this by calling `common.initialize_run` exactly once itself and passing the resulting `logger`/`device` into both `train.run_train(...)` and `evaluate.run_evaluate(...)`, so a combined run produces one `run_{debug,info,error}.log` set instead of separate `train_*`/`evaluate_*` files.

## 1. `pytorch/common.py` (new)

Add three functions, extracted near-verbatim from `run_dnn.py` (behavior-preserving except where a gap fix is called out above):

- `initialize_run(self_dir, self_name, params) -> (logger, device)`: from `run_dnn.py:44-90` — CPU/device detection, random seed fixing (mutating `params["runconfig"]["random_seed"]` to `None` when absent, as today), `logging_set_up(self_dir / params["runconfig"]["save_dir"] / self_name)`, environment log lines (drop the `Mode`/`Data key` lines, which move to each caller since they differ per script), and the `enable_debug` parameter pretty-print block. `self_name` is always the caller's own `pathlib.Path(__file__).stem` (`"train"` in `train.py`, `"evaluate"` in `evaluate.py`, `"run"` in `run.py`), matching `run_dnn.py:43`'s existing `self_name = pathlib.Path(__file__).stem` convention. Meant to be called exactly once per process; see "single log-file set" in Terminology for why a combined `run.py` invocation only calls this once.
- `load_and_preprocess_data(params, logger) -> (features, targets, features_noise, targets_noise, targets_scale, targets_noise_scale, features_transform_fn, train_input_transform_fn)`: from `run_dnn.py:96-194` minus the `create_dataloader` call at the end (each caller builds its own dataloader(s)) — `load_data`, `preprocess_features`/`preprocess_targets` (x2, main + noise), the `features_fft` closure (`run_dnn.py:126-143`), and the `autoencoder_load_dir` block (`run_dnn.py:145-182`) that builds `train_input_transform_fn`. Keep the `####DEV`/`####/DEV` markers as-is, but convert the block's file operations from `os.path.join`/`glob.glob`/`os.path.getmtime` to `pathlib.Path.glob`/`Path.stat().st_mtime` (e.g. `(pathlib.Path(autoencoder_load_dir) / "checkpoints").glob("*")`), matching the pathlib-only style used everywhere else in `common.py`; drop the block's now-unneeded `import glob` line.
- `find_latest_checkpoint(checkpoint_root: pathlib.Path) -> pathlib.Path`: new helper generalizing the glob+mtime pattern from `run_dnn.py:154-160` to `checkpoint_root/checkpoints/*` (latest timestamp folder) then `*.pt` inside it (latest file), implemented with `pathlib.Path.glob`/`Path.stat().st_mtime` rather than `glob.glob`/`os.path.getmtime`; raises a clear `FileNotFoundError` if no checkpoint folder/file exists yet, so `evaluate.py` fails fast with an actionable message instead of a raw glob error.

## 2. `pytorch/train.py` (new)

`run_train(params, logger=None, device=None)`:

- `self_dir = pathlib.Path(__file__).parent`.
- `mode = get_mode_from_name(params["runconfig"]["mode"])`; require `Mode.TRAIN in mode` (a lenient bit check, not exact equality, so `run.py` can pass a combined mode like `train_eval` straight through), else raise `ValueError`. The stricter "only `train`/`train_profile` allowed" check lives in `main()` instead (see below), since that is the CLI-facing entrypoint that should reject unrelated modes outright.
- `if logger is None or device is None: logger, device = common.initialize_run(self_dir, pathlib.Path(__file__).stem, params)` (skipped when `run.py` already built these, so a combined run produces one log-file set instead of two, per "single log-file set" in Terminology); log `Mode` and the training data key (`"train"`) itself, mirroring the dropped lines from `run_dnn.py:82-83`.
- `features, targets, features_noise, targets_noise, _, _, features_transform_fn, train_input_transform_fn = common.load_and_preprocess_data(params, logger)`.
- Build the single training dataloader via `create_dataloader(params, logger, mode, features=features["train"], targets=targets["train"], features_noise=features_noise["train"], targets_noise=targets_noise["train"], features_transform_fn=features_transform_fn)`, matching `run_dnn.py:184-194` with `mode_to_data_key` fixed to `"train"`.
- `net = nets.create_network(params, device, logger)` (writes `net.txt` and transfers `net` to `device` internally, `nets.py:271-382`); if `params["runconfig"].get("load_checkpoint")` is set, resume by calling `dlk.opt.utils.checkpoint_load(self_dir / load_checkpoint, net, map_location=device)` (fixes the mismatch bug from `run_dnn.py:204-206` for the resume path too).
- Training body, moved verbatim from `run_dnn.py:215-270`: create optimizer/scheduler, `loss_fn = torch.nn.MSELoss()`, checkpoint dir/epochs, branch on `Mode.PROFILE in mode` for `profile_train_batches` vs. `train_epochs`.
- Output section, the training-only subset of `run_dnn.py:364-382`: log `Runtime - train [sec]` and the `#epochs`/`#steps`/`#samples`/`avg. steps-samples per sec` block (now reading `params["data_train"]["Ntrain"]`/`["train_batch_size"]` unconditionally, since this file only ever runs the train path), then `plot_loss(train_dlog["loss_mean"], ...)` from `run_dnn.py:393-403`.

`main()`: `config_params.add_args_to_parser(parser, default_params_path="configs/params_dnn.yaml", default_mode="train")`, load/override `params`; validate `get_mode_from_name(params["runconfig"]["mode"]) in {Mode.TRAIN, Mode.TRAIN | Mode.PROFILE}`, raising `ValueError` naming the allowed values (`train`, `train_profile`) and pointing at `evaluate.py`/`run.py` otherwise; save `params` exactly as `run_dnn.py:504-528`, then call `run_train(params)` (no `logger`/`device`, so it builds its own).

## 3. `pytorch/evaluate.py` (new)

`run_evaluate(params, logger=None, device=None)`:

- `self_dir = pathlib.Path(__file__).parent`.
- `mode = get_mode_from_name(params["runconfig"]["mode"])`; require `mode.any(Mode.PREDICT | Mode.EVAL)` (a lenient bit check, not exact equality, so `run.py` can pass a combined mode like `train_eval` straight through), else raise `ValueError`. The stricter "only `predict`/`eval` allowed" check lives in `main()` instead (see below).
- `if logger is None or device is None: logger, device = common.initialize_run(self_dir, pathlib.Path(__file__).stem, params)` (skipped when `run.py` already built these, so a combined run produces one log-file set instead of two, per "single log-file set" in Terminology); log `Mode`.
- `features, targets, features_noise, targets_noise, targets_scale, targets_noise_scale, features_transform_fn, train_input_transform_fn = common.load_and_preprocess_data(params, logger)` (same full train+validate+test pool as today, since the plotting loop below needs all three splits, matching `run_dnn.py:281-293`).
- `net = nets.create_network(params, device, logger)` (writes `net.txt` and transfers `net` to `device` internally, `nets.py:271-382`).
- Resolve the checkpoint to load: `load_checkpoint = params["runconfig"].get("load_checkpoint")`; if set, `checkpoint_path = self_dir / load_checkpoint` (used directly, no discovery); otherwise `checkpoint_path = common.find_latest_checkpoint(self_dir / params["runconfig"]["save_dir"])`. Either way, `epoch = dlk.opt.utils.checkpoint_load(checkpoint_path, net, map_location=device)` (no extra `net.to(device)` needed: `nets.create_network` already places `net` on `device`, and `checkpoint_load`'s `map_location=device` loads the state dict directly onto it); log the resolved path and epoch.
- Build `eval_dataloader` per split exactly as `run_dnn.py:282-293`, dropping the unused primary `dataloader` that `run_dnn.py:184-194` builds in eval-only mode today (the gap noted in Context).
- Predict + postprocess, moved verbatim from `run_dnn.py:296-323` (the `predict()` and `eval_data_vs_pred()` helper functions at `run_dnn.py:455-474` and `run_dnn.py:477-498` move into `evaluate.py` unchanged, since neither is used by `train.py`).
- If `Mode.EVAL in mode`: compute and log MSE/MAE/R2 exactly as `run_dnn.py:336-355`.
- Output section, the eval-only subset of `run_dnn.py:363-392` (log `Runtime - eval [sec]` and the `#samples`/`avg. samples/sec` block, reading `params["data_evaluate"]["Ntest"]`/`["eval_batch_size"]`), then the prediction/error plot loop from `run_dnn.py:408-444` (per-split `plot_data_vs_predict`/`plot_data_vs_predict_error`, using the same `n_key`/`params["data_train"].get(n_key, params["data_evaluate"].get(n_key))` lookup at `run_dnn.py:410-413`), and the `show_plots` handling at `run_dnn.py:445-447`.

`main()`: `config_params.add_args_to_parser(parser, default_params_path="configs/params_dnn.yaml", default_mode="eval")`, load/override `params`; validate `get_mode_from_name(params["runconfig"]["mode"]) in {Mode.PREDICT, Mode.EVAL}`, raising `ValueError` naming the allowed values (`predict`, `eval`) and pointing at `train.py`/`run.py` otherwise; save `params`, then call `run_evaluate(params)` (no `logger`/`device`, so it builds its own).

## 4. `pytorch/run.py` (new)

Thin composition script, not a copy of `run_dnn.py`'s body:

- `self_dir = pathlib.Path(__file__).parent`. `main()`: `config_params.add_args_to_parser(parser, default_params_path="configs/params_dnn.yaml", default_mode="train_eval")` (full choice set, matching `run_dnn.py`'s current default), load/override `params`, save `params` once.
- `logger, device = common.initialize_run(self_dir, pathlib.Path(__file__).stem, params)` (`self_name` resolves to `"run"`), called exactly once so the combined invocation writes a single `run_debug.log`/`run_info.log`/`run_error.log` set instead of separate `train_*`/`evaluate_*` files (see "single log-file set" in Terminology).
- `mode = get_mode_from_name(params["runconfig"]["mode"])`; `if Mode.TRAIN in mode: train.run_train(params, logger=logger, device=device); params["runconfig"]["load_checkpoint"] = None` (reset only after an actual training run, so `evaluate.run_evaluate` below auto-discovers the checkpoint `train.py` just wrote under `save_dir` instead of reloading whatever `load_checkpoint` training resumed from); `if mode.any(Mode.PREDICT | Mode.EVAL): evaluate.run_evaluate(params, logger=logger, device=device)`.
- No mode restriction beyond `run_train`/`run_evaluate`'s own lenient bit checks (`Mode.TRAIN in mode` / `mode.any(PREDICT | EVAL)`). For example `train_profile` mode has no `PREDICT`/`EVAL` bits, so the `if mode.any(PREDICT | EVAL)` guard skips evaluation entirely, matching `run_dnn.py`'s current behavior where `run_dnn.py:276-277` already returns before `<predict>` in that mode.

## Usage sketch

Before (single combined invocation):

```bash
uv run python run_dnn.py --params configs/params_dnn.yaml --mode train_eval --save_dir runs/fhn_data2020
```

After (two independent invocations, same config file, same `save_dir`):

```bash
uv run python train.py --params configs/params_dnn.yaml --save_dir runs/fhn_data2020
uv run python evaluate.py --params configs/params_dnn.yaml --save_dir runs/fhn_data2020
```

`evaluate.py` loads the checkpoint from `--save_dir` by default and auto-discovers the checkpoint `train.py` just wrote. Equivalent combined invocation via the new wrapper:

```bash
uv run python run.py --params configs/params_dnn.yaml --save_dir runs/fhn_data2020
```

## Risks / edge cases

- Under the old `run_dnn.py`, a combined `train_eval` run evaluates the in-memory `net` object right after training, never reloading from disk. After the split (including via the new `run.py`), `evaluate.py` always reloads weights from the checkpoint file `train.py` just saved. Results should match closely (same weights, same seed) but are not guaranteed bit-identical, since the reload also strips through `state_dict()`/`load_state_dict()` serialization; call this out explicitly if the smoke-run diff (Verification step 3) shows any numeric drift.
- `checkpoint_save` only writes a checkpoint at epochs where `epoch_idx % checkpoint_epochs == 0` plus a final save after training completes (`dlk/opt/train.py:117-127,169-173`), so `find_latest_checkpoint` will always find at least the final checkpoint for any completed `train.py` run; a `train.py` run interrupted before its first checkpoint epoch leaves nothing for `evaluate.py` to find, and `find_latest_checkpoint` should raise a clear error in that case rather than an obscure glob failure.
- If a user points `evaluate.py`'s `runconfig.load_checkpoint` at a checkpoint file trained with a different `net:` architecture (e.g. edited the config since that checkpoint was written), `checkpoint_load`'s `load_state_dict` will raise a shape/key-mismatch error; this is expected and not specific to the split, but worth a one-line mention in `evaluate.py`'s docstring since it is now a more likely mistake (two separate script invocations instead of one).
- `evaluate.py` writing to the same `runconfig.save_dir` as `train.py` means both scripts overwrite the same `net.txt` and `params.yaml` with equivalent content; this is idempotent (same architecture, same params dict) but means `evaluate.py`'s `params.yaml` write happens after `train.py`'s and will reflect whatever `--json_params`/`--toml_params` overrides were passed to `evaluate.py`'s own invocation, which may differ slightly from what `train.py` was run with if the user is not careful to pass matching overrides to both.
