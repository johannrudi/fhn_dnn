# Evaluate train/validate splits on every checkpoint

Created with the skill: `deep-learning-toolkit/.agents/skills/plan-feature`

## Context

`pytorch/evaluate.py`'s `run_evaluate` (`evaluate.py:39-251`) currently loads exactly one checkpoint (`runconfig.load_checkpoint` if set, else the newest `.pt` under `runconfig.save_dir` via `common.find_latest_checkpoint`, `evaluate.py:123-133`), then predicts and (optionally) scores all three splits (`train`, `validate`, `test`) from that single checkpoint (`evaluate.py:102-116` builds one dataloader per key in `features.keys()`, `evaluate.py:137-241` predicts/scores/plots all of them together). The user wants `train`/`validate` evaluated at every checkpoint written during training (to see how the network's fit on those splits evolves across epochs), while `test` keeps being evaluated at a single checkpoint only, exactly as today.

Two gaps in the current code directly affect this change, both settled below:

- **Runtime-stats sample count is `Ntest`-only**: `evaluate.py:201-203` computes `n_samples` solely from `params["data_evaluate"]["Ntest"] // eval_batch_size`, regardless of which splits were actually predicted; it also silently drops the remainder batch even though `create_dataloader` sets `drop_last=False` (`data.py:1034`), so the true sample count is always `len(dataloader.dataset)`, not a floor-divided approximation. This calculation cannot survive as-is once `train`/`validate` are evaluated separately from `test`, so it is fixed as part of this refactor rather than carried forward.
- **`common.find_latest_checkpoint` duplicates the glob+mtime pattern**: this change adds a sibling `find_all_checkpoints` that lists every checkpoint in the run's latest timestamp folder; `find_latest_checkpoint` becomes a one-line wrapper (`find_all_checkpoints(...)[-1]`) instead of repeating the glob logic (`common.py:208-247`).

### Settled design decisions

- Looping over every checkpoint is the default behavior of `evaluate.py`'s `train`/`validate` pass; there is no separate opt-in/opt-out config flag. This default naturally depends on `runconfig.save_dir` being set, since that is the only input `common.find_all_checkpoints` uses to locate checkpoints; if `save_dir` is not set, the checkpoint sequence is not evaluated (the loop has nothing to iterate over), the same precondition `common.find_latest_checkpoint` already has for the `test` path today.
- `train`/`validate` evaluation is one code path that always auto-discovers every checkpoint file under `runconfig.save_dir`'s `checkpoints/<latest timestamp>/` folder (via new `common.find_all_checkpoints`) and runs on all of them, including whichever one is also the "last" checkpoint; `runconfig.load_checkpoint` has no effect on this path.
- `test` evaluation is a separate code path, unchanged in spirit from today: it uses `runconfig.load_checkpoint` when set, otherwise auto-discovers the latest checkpoint via `common.find_latest_checkpoint`; it always evaluates exactly one checkpoint.
- All `train`/`validate` plot output moves into a new per-checkpoint subdirectory `runconfig.save_dir/checkpoints_eval/<checkpoint file stem>/` (e.g. `checkpoints_eval/net_e0040/`), using the same filenames used today (`data_vs_predict_train.pdf`, `predict_error_train.pdf`, `data_vs_predict_validate.pdf`, `predict_error_validate.pdf`). This applies even to the checkpoint that happens to be numerically last; the flat, unsuffixed `save_dir/data_vs_predict_{train,validate}.pdf` / `predict_error_{train,validate}.pdf` files this script writes today are no longer produced (see Risks).
- `test` plot output keeps its current flat location and filenames unchanged: `save_dir/data_vs_predict_test.pdf`, `save_dir/predict_error_test.pdf`.
- MSE/MAE/R2 log lines and the `Runtime` log lines gain a `[<checkpoint stem>]` tag when they come from the `train`/`validate` loop, so repeated per-checkpoint lines stay distinguishable in the log file; the `test` path keeps its exact current (untagged) log line format.
- A new aggregate output is added: after the `train`/`validate` loop finishes, plot overall MSE/MAE/R2 against checkpoint epoch for each of `train` and `validate`, saved as `save_dir/metrics_vs_checkpoint_{train,validate}.pdf` (+ `.txt` raw dump), via a new `plot_utils.plot_metrics_vs_checkpoint`. This only runs when `Mode.EVAL in mode` (same gate as the existing MSE/MAE/R2 computation).
- The network (`nets.create_network`) and the `train`+`validate` dataloaders are each built exactly once per `evaluate.py` invocation and reused across every checkpoint in the loop; only the weights loaded into `net` change per iteration (`checkpoint_load` overwrites `net`'s `state_dict` in place).
- The `test` dataloader is built once as its own single-key dict, independent of the `train`/`validate` dataloader dict, since it now follows a separate code path.

### Core principle

`train`/`validate` and `test` become two independent evaluation passes inside `run_evaluate`, sharing the same low-level helpers (predict, postprocess, score, plot) but differing in which checkpoint(s) they load and where they write output. The `train`/`validate` pass is a loop over `common.find_all_checkpoints(...)`; the `test` pass is the single-checkpoint flow that exists today, untouched in its checkpoint-resolution logic and its output paths.

## Terminology

- **checkpoint stem**: `pathlib.Path.stem` of a checkpoint file, e.g. `net_e0040` for `net_e0040.pt` (the zero-padded epoch number comes from `dlk.opt.utils.checkpoint_path`, `deep-learning-toolkit/dlk/opt/utils.py:72-93`). Used directly as the subfolder name under `checkpoints_eval/` and as the `[...]` log tag, so no new digit-padding logic is needed in this repo.
- **`checkpoints_eval/`**: new output subdirectory under `runconfig.save_dir`, one child folder per evaluated checkpoint, holding that checkpoint's `train`/`validate` plots.
- **`common.find_all_checkpoints(checkpoint_root)`**: new helper returning every `*.pt` file inside `checkpoint_root/checkpoints/<latest timestamp folder>`, sorted by mtime ascending (oldest/lowest-epoch first). `common.find_latest_checkpoint` becomes `find_all_checkpoints(...)[-1]`.
- **metrics-vs-checkpoint plot**: new plot (`plot_utils.plot_metrics_vs_checkpoint`) with three side-by-side panels (MSE, MAE, R2, each the overall scalar returned by `eval_data_vs_pred`) plotted against checkpoint epoch, one figure per split (`train`, `validate`).

## 1. `pytorch/common.py`

Pre-change lines: `common.py:208-247` (`find_latest_checkpoint`).

- Add `find_all_checkpoints(checkpoint_root: pathlib.Path) -> list[pathlib.Path]`: locates the latest timestamp subfolder under `checkpoint_root/checkpoints/` exactly as today (`common.py:225-239`), then returns *all* `*.pt` files in it (`latest_folder.glob("*.pt")`) sorted by `p.stat().st_mtime` ascending, instead of picking only the max. Raises the same `FileNotFoundError`s as today (no checkpoints directory, no timestamp subfolders, no `.pt` files) with the same messages.
- Rewrite `find_latest_checkpoint` to `return find_all_checkpoints(checkpoint_root)[-1]`, removing its now-duplicated glob body.

## 2. `pytorch/plot_utils.py`

Pre-change lines: end of file, after `plot_data_vs_predict_error` (`plot_utils.py:140-184`).

Add `plot_metrics_vs_checkpoint(epochs, mse, mae, r2, path, plot_name="", save_txt=True, save_plot=True)`: saves the four equal-length sequences as columns to `{path}.txt` when `save_txt`; creates a `1x3` subplot figure (mirroring the `n_plots` subplot pattern in `plot_data_vs_predict_error`, `plot_utils.py:161-162`) with panels titled `MSE`, `MAE`, `R2`, each plotting `ax.plot(epochs, values, "o-")` against the epoch on the x-axis, `ax.set_xlabel("epoch")`, grid enabled; the whole figure's suptitle (or each panel's title prefix) uses `plot_name` (the split name, `"train"` or `"validate"`) so the two output files are visually distinguishable; saves to `{path}.pdf` when `save_plot`.

## 3. `pytorch/evaluate.py`

Pre-change lines: `run_evaluate` body (`evaluate.py:39-251`), `predict` (`evaluate.py:254-289`), `eval_data_vs_pred` (`evaluate.py:292-326`, unchanged).

Extract four module-level helpers from the current `run_evaluate` body, each taking the pieces of state they need as arguments (no hidden globals), so `run_evaluate` calls each helper once per checkpoint in the loop and once for `test`:

- `_predict_and_postprocess(net, eval_dataloader, device, targets, targets_noise, targets_scale, targets_noise_scale, train_input_transform_fn) -> tuple[dict, dict, float]`: wraps today's predict-timing block (`evaluate.py:137-149`) and the scale-selection/postprocess `if`/`elif`/`else` (`evaluate.py:151-169`) unchanged (the `if dictarray_is_not_none(...)` branching and `postprocess_targets` calls do not depend on which split keys are present in `eval_dataloader`, since `targets_scale`/`targets_noise_scale` are single shift/mult dicts, not per-split, see `data.py:592-619`). Returns `(eval_targets_pred, eval_targets_data, time_eval)`.
- `_log_eval_metrics(eval_targets_data, eval_targets_pred, mode, logger, tag="") -> dict[str, dict[str, float]] | None`: wraps today's `Mode.EVAL in mode` block (`evaluate.py:175-193`) verbatim except every log line becomes `f"MSE ({key}){tag}:      " + ...` (and same for MAE/R2), so `tag=""` reproduces today's exact `test`-path log format and `tag=f" [{checkpoint_path.stem}]"` is used in the loop. Returns `None` when `Mode.EVAL not in mode`; otherwise returns `{key: {"mse": eval_mse[key], "mae": eval_mae[key], "r2": eval_r2[key]}}` for every key present, used by the caller to build the aggregate plot.
- `_log_runtime(logger, time_eval, n_samples, tag="")`: wraps today's runtime-stats block (`evaluate.py:199-205`), replacing the `Ntest`-derived `n_samples` computation with a caller-supplied `n_samples` (see Context gap); log lines become `f"Runtime{tag} [sec]: ..."` etc., so `tag=""` keeps the `test` path's log text identical to today.
- `_plot_predictions(eval_targets_data, eval_targets_pred, params, output_dir)`: wraps today's plotting loop (`evaluate.py:207-241`) unchanged except `path = self_dir / params["runconfig"]["save_dir"] / f"..."` becomes `path = output_dir / f"..."`, and `output_dir.mkdir(parents=True, exist_ok=True)` is called first (new folders under `checkpoints_eval/` do not exist yet).

Rewrite `run_evaluate`'s body (after the existing `<init>`/`<data>` sections, `evaluate.py:61-100`, which stay as-is) as:

1. Build two dataloader dicts instead of one loop over `features.keys()` (`evaluate.py:102-116`): `train_validate_dataloader = {key: create_dataloader(...) for key in ("train", "validate")}` and `test_dataloader = {"test": create_dataloader(...)}`, both via the same `create_dataloader(params, logging_get_logger("create_dataloader"), Mode.EVAL, features=features[key], targets=targets[key], features_noise=features_noise[key], targets_noise=targets_noise[key], features_transform_fn=features_transform_fn)` call used today.
2. `net = create_network(...)` once (`evaluate.py:121`, unchanged, moved above both passes).
3. **`train`/`validate` pass**: `checkpoints = common.find_all_checkpoints(self_dir / params["runconfig"]["save_dir"])`; initialize `metrics_by_epoch = {"train": {"epoch": [], "mse": [], "mae": [], "r2": []}, "validate": {"epoch": [], "mse": [], "mae": [], "r2": []}}`; loop `for checkpoint_path in checkpoints:` — `epoch = checkpoint_load(checkpoint_path, net, map_location=device)`; log `f"Evaluate checkpoint {checkpoint_path} (epoch {epoch}) for train/validate"`; call `_predict_and_postprocess` with `train_validate_dataloader`; call `_log_runtime` with `n_samples = sum(len(dl.dataset) for dl in train_validate_dataloader.values())` and `tag=f" [{checkpoint_path.stem}]"`; call `_log_eval_metrics` with the same tag, and when it returns non-`None`, append `epoch` and each split's `mse`/`mae`/`r2` into `metrics_by_epoch`; call `_plot_predictions(..., output_dir=self_dir / params["runconfig"]["save_dir"] / "checkpoints_eval" / checkpoint_path.stem)`.
4. **Aggregate plot**: `if Mode.EVAL in mode and checkpoints:` for each of `"train"`, `"validate"`, call `plot_metrics_vs_checkpoint(metrics_by_epoch[key]["epoch"], metrics_by_epoch[key]["mse"], metrics_by_epoch[key]["mae"], metrics_by_epoch[key]["r2"], self_dir / params["runconfig"]["save_dir"] / f"metrics_vs_checkpoint_{key}", plot_name=key)`.
5. **`test` pass**, checkpoint resolution unchanged from today (`evaluate.py:124-133`): resolve `test_checkpoint_path` from `runconfig.load_checkpoint` or `common.find_latest_checkpoint`; `epoch = checkpoint_load(test_checkpoint_path, net, map_location=device)`; log exactly as today (`evaluate.py:133`); call `_predict_and_postprocess` with `test_dataloader`; call `_log_runtime` with `n_samples = len(test_dataloader["test"].dataset)` and `tag=""`; call `_log_eval_metrics` with `tag=""`; call `_plot_predictions(..., output_dir=self_dir / params["runconfig"]["save_dir"])` (flat, today's paths).
6. `show_plots` handling (`evaluate.py:242-247`) stays, applied once at the end after both passes.

`predict` (`evaluate.py:254-289`) and `eval_data_vs_pred` (`evaluate.py:292-326`) are unchanged; `main()` (`evaluate.py:329-373`) is unchanged.

## Usage sketch

Before (single checkpoint, all three splits):

```bash
uv run python evaluate.py --params configs/params_dnn.yaml --save_dir runs/fhn_data2020
# -> runs/fhn_data2020/data_vs_predict_{train,validate,test}.pdf, predict_error_{train,validate,test}.pdf
```

After (same command, now covers every checkpoint for train/validate, one checkpoint for test):

```bash
uv run python evaluate.py --params configs/params_dnn.yaml --save_dir runs/fhn_data2020
# -> runs/fhn_data2020/checkpoints_eval/net_e0000/data_vs_predict_{train,validate}.pdf, predict_error_{train,validate}.pdf
# -> runs/fhn_data2020/checkpoints_eval/net_e0040/data_vs_predict_{train,validate}.pdf, predict_error_{train,validate}.pdf   (one folder per checkpoint)
# -> runs/fhn_data2020/metrics_vs_checkpoint_{train,validate}.pdf   (new aggregate plot)
# -> runs/fhn_data2020/data_vs_predict_test.pdf, predict_error_test.pdf   (unchanged location/filenames)
```

## Risks / edge cases

- Removing the flat `save_dir/data_vs_predict_{train,validate}.pdf` / `predict_error_{train,validate}.pdf` outputs is a breaking change for anything that reads those specific paths (e.g. a notebook or downstream script); they now live under `checkpoints_eval/<last checkpoint stem>/` instead. Worth a one-line mention to the user if they have external tooling pointed at the old flat paths.
- A run with only one checkpoint (e.g. `save_checkpoints_epochs` left at a value larger than `training.epochs`, so only the pre-training epoch-0 checkpoint and the final checkpoint exist, or a config where checkpointing produces just one file) still works, just yields a 1-2 point `metrics_vs_checkpoint_*` plot; not an error case.
- Re-evaluating `train`/`validate` at the epoch-0 (pre-training) checkpoint, which `dlk.opt.train.train_epochs` always writes when `checkpoint_epochs` divides evenly into epoch 0 (`dlk/opt/train.py:117-127`), means the first `checkpoints_eval/net_e0/` folder reflects an untrained network; expected, not a bug, but worth noting so the aggregate plot's first point is not mistaken for a broken run.
- The `test` pass reloads whichever checkpoint it resolves into the same `net` object the loop already used, so that checkpoint's weights are loaded twice (once in the loop, once for `test`) when it happens to be the same file; this is intentional per the settled decision to keep the two passes independent, and is cheap relative to prediction cost.
- `_log_runtime`'s corrected `n_samples` (Context gap) changes the exact `avg. samples/sec` figure logged for the `test` path compared to before (previously floor-divided, now the true dataset length); if anything parses that log line for regression tracking, its expected value shifts slightly.
